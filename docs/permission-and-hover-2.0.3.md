# 2.0.3 授权反馈与拖放稳定性

授权浮窗采用系统设置默认 246 pt 固定侧栏和 20 pt 内容边距计算宽度，左右边缘与右侧内容卡片对齐。会随设置窗口和显示器可见区域调整，底部空间不足时保持在屏幕内，不增加辅助功能或屏幕录制权限。

| 阶段 | 反馈 | 行为 |
| --- | --- | --- |
| 等待拖入 | 拖入列表或使用系统“+” | 保留关闭入口 |
| 拖动中 | 松开以添加 | 保持源视图与窗口，延后关闭 |
| 拖放接受 | 开启开关、正在检测 | 200 ms 刷新；不把拖放成功当作授权 |
| 暂未检测到 | 检查开关或重试 | 继续检测 |
| 系统已记录权限 | 授权完成，必要时提示重启 | 展示约 0.7 秒，关闭浮窗和 DropPoint 设置，向此次跟随的系统设置进程发出正常退出请求 |

跳过、关闭或超时不关闭系统设置；期间撤销授权会取消完成状态。重启需求仍在 DropPoint 设置中保留，不静默重启应用。

收到本轮报告时，系统尚无新的崩溃报告，最新可读堆栈仍是旧版 2.0.0 的 SwiftUI 悬停路径。因此不能把这次用户操作与某个新堆栈直接对应。新增测试复现了关闭后 mouseEntered/mouseExited 仍更新界面的遗漏，现与 mouseMoved 一起关闭。macOS 27 自定义控件改用 AppKit 跟踪区域，保留悬停样式并避开 NSHostingView 的悬停分发；点击、键盘和原生拖放仍使用原有路由。

锁屏下的回归还发现动画完成回调可能迟到，原先依赖回调的关闭逻辑会错过完成时限。现在动画回调与 250 ms 的兜底竞争完成同一显示代次，仅执行一次，关闭仍等待拖出结束。测试覆盖关闭等待、隐藏升级为关闭、禁止复活和迟到悬停。

本轮结果：109 项 XCTest，108 通过、1 项实际窗口截图因未获权限跳过，0 失败。包含权限阶段、完成后关闭回调、等宽布局、负坐标显示器、并发日志完整性、轮换和快照。浅深色浮窗离屏布局已检查，不能代替实际授权、第三方来源长时间拖放及多设备测试。诊断范围见 [日志说明](diagnostics.md)。
